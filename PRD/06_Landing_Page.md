# Landing Page

## Overview

The landing surface is the entire site. There are no other pages. A user lands here, generates, downloads, and either leaves or sends the result. This file specifies the layout above the fold, the hero examples that do most of the explaining, the footer, the OG card metadata, and the JS-required fallback.

The first-impression beat ("oh, this is going to be good") is the third-most-important emotional moment in the journey. Get the hero wrong and users bounce before generating.

## Dependencies
- `04_UI_Design_System.md` — All colors, typography, spacing tokens
- `07_Input_And_Presets.md` — The prompt input and presets, which live below the hero examples
- `15_Compositing_Engine.md` — Hero examples are real composites, rendered by the same engine
- `16_Poster_Display_And_Regenerate.md` — The poster reveal area, which appears below the hero only after the first generation

## Page Structure (Above the Fold)

```
┌─────────────────────────────────────────────────────┐
│ Bless Your Heart                            (header) │
├─────────────────────────────────────────────────────┤
│                                                      │
│         What's going on?         (display headline)  │
│                                                      │
│         [ hero example posters: 1 mobile, 3 desktop ]│
│                                                      │
│         [ "What's going on?" prompt input field ]    │
│                                                      │
│         [ preset chips: Monday again · Work · ... ]  │
│                                                      │
│                  [ Generate ]                        │
│                                                      │
└─────────────────────────────────────────────────────┘
```

**Critical**: the prompt input AND the Generate button must sit above the fold on iPhone SE (375×667) and on standard 13" laptop displays (1280×800). Test both before shipping. Hero examples shrink to one on mobile, expand to three on desktop.

## Header

A single line. The wordmark "*Bless Your Heart*" in Cormorant Garamond italic at `text-headline` size (32px mobile / 40px desktop), `ink-deep` color, centered or left-aligned (designer's call — both work). No logo mark, no tagline, no nav links. The wordmark is also a link to `/` so users coming back via search can re-anchor.

Padding: ~24px vertical, no bottom border. The header should feel like part of the page, not a chrome bar.

## Hero Display Headline

The single anchoring question:

> ***What's going on?***

Set in `text-display` (48px mobile / 60px desktop), italic, `ink-deep`. This headline IS the prompt — it both labels the input field and serves as the page's voice. The actual `<input>` placeholder doubles down on this with example phrases (see `07_Input_And_Presets.md`).

No subheadline. No "Generate poetic mockery of your bad day in seconds." Resist the urge. The hero examples explain the product; the headline only sets the tone.

## Hero Examples

Three pre-rendered example posters that demonstrate the format without explanation. They are the pitch. They do more work than any copy could.

**Why this matters most**: A first-time visitor decides whether to engage in 2–3 seconds. If the examples don't land, the user bounces and the product never gets a chance. The examples should be *the funniest possible* version of the format — calibrated, not the first three a developer drafts.

### Example specs

- **Count**: 3 on desktop (`lg+`), 1 on mobile. The mobile example rotates randomly per page-load from the pool of three.
- **Size**: ~280px square on mobile, ~320–360px square on desktop. They render small enough that the prompt stays above the fold but large enough that line 2 is readable.
- **Render path**: They are *real composites* generated by `15_Compositing_Engine.md`, using fixed text and curated photos from the library. Pre-render at build time and ship as static images in `public/examples/` to avoid running the compositor on landing.
- **No interactivity**: examples are not clickable, don't have a "use this" button, and don't link anywhere. They sit there and do their job.

### Example content (author during build)

These are placeholders — author the actual lines after the voice prompt is tuned. Each example showcases a different kind of input, so the user sees range:

| Example | Input premise | Line 1 | Line 2 |
|---------|---------------|--------|--------|
| 1 | A pure feeling | (e.g.) *Some sunsets are reminders.* | *That tomorrow is also Monday.* |
| 2 | A specific situation | *Healing isn't linear.* | *Yours, in particular, is a flat line.* |
| 3 | Something universal | *You are exactly where you need to be.* | *Statistically, this is bad news.* |

These are illustrative. Author the real ones with the prompt + a manual review pass — they're the storefront.

**Critical content note**: Don't show off-topic examples as hero examples. Reserve the meta-bit for users who go looking for it.

## Hero Layout (CSS notes)

- Centered column, max-width ~640px on desktop, full-width with padding on mobile.
- Vertical rhythm uses `space-breathe` (28px) between elements; the gap between the headline and the example row is `space-section` (64px).
- Example row uses CSS grid (`grid-cols-3` on desktop, `grid-cols-1` on mobile) with a `gap-4`.
- Background is `bg-cream`; no card lift behind the hero. Flat, not layered.

## Below the Fold

Once the user generates, the poster reveal area appears below the prompt (does not push the hero off-screen, does not navigate). Scrolling is natural after generation; the reveal animation in `16_Poster_Display_And_Regenerate.md` triggers a soft scroll-into-view if the poster is partially clipped.

Returning generations replace the previous poster in the same slot — no scrolling carousel of past generations on the page. Per `07_Input_And_Presets.md`, the input persists; per the anti-features in `00_README.md`, no public history surfaces.

## Footer

Lives at the bottom of the page, below all generated content. Always visible after scroll.

```
─────────────────────────────────────────────────
Bless Your Heart · made with affection and resignation
A comedy product, not therapy. If you're in crisis, please reach out:
988 (US) · findahelpline.com (worldwide)
Photos: see credits · © Builder Name
─────────────────────────────────────────────────
```

Set in `text-caption`, `ink-faint`, `bg-paper` background, ~32px vertical padding. The crisis line is the only "serious" copy on the entire site and it earns its place — both for user safety and for tone-cover.

The "see credits" link opens a simple dialog (or scrolls to a hidden section) listing photographer credits per `03_Data_Schema.md`'s `credit` field. Do not name every photographer in the visible footer — too cluttered.

## OG Card Metadata

When users paste the URL into iMessage, Slack, X, or anywhere else with link previews, the card is the discovery surface. Treat it as carefully as the landing hero.

```html
<meta property="og:title" content="Bless Your Heart" />
<meta property="og:description" content="The honest motivational posters you didn't ask for." />
<meta property="og:image" content="https://blessyourheart.app/og-hero.png" />
<meta property="og:url" content="https://blessyourheart.app/" />
<meta property="og:type" content="website" />
<meta name="twitter:card" content="summary_large_image" />
<meta name="twitter:title" content="Bless Your Heart" />
<meta name="twitter:description" content="The honest motivational posters you didn't ask for." />
<meta name="twitter:image" content="https://blessyourheart.app/og-hero.png" />
```

**OG image**: A single canonical "house example" poster, 1200×630, rendered by the compositor at build time and saved to `public/og-hero.png`. This is the most-seen image of the entire site over its lifetime — the one example the developer agonizes over.

## JS-Required Fallback

The product genuinely cannot work without JavaScript (Canvas compositing, the API call, the input form all need it). Better to be honest than to half-load.

In `<noscript>`:

```html
<noscript>
  <div class="noscript-fallback">
    <h1>Bless Your Heart</h1>
    <p>This corner of the internet requires JavaScript. The universe also asks
    a lot of you. Try enabling it and we can both get on with the moment.</p>
  </div>
</noscript>
```

In voice. No exclamation points. The copy itself is a small joke that rewards the user who notices.

## Page Title and Meta

```html
<title>Bless Your Heart</title>
<meta name="description" content="The honest motivational posters you didn't ask for." />

```

`theme-color` matches `bg-cream` so mobile browsers tint the address bar in the brand palette. Small but felt.

## Performance Notes

- Hero example images are pre-rendered PNGs, served from `/public/`. Netlify edge-caches them automatically. Set `<img loading="eager" fetchpriority="high">` on these — they are above the fold and visible immediately.
- The font CSS imports (`@fontsource/cormorant-garamond/*`) load synchronously during the JS bundle. Cormorant Garamond regular at 400 must be cached locally before render — see `23_Performance.md` for preload strategy.
- Total above-the-fold weight target: under 250 KB compressed (HTML + CSS + JS bundle + 1 hero image). Achievable with this stack; verify with Lighthouse before launch.

## Gaps & Assumptions

- **OG image generation**: No automated build step. Render the canonical poster manually using the curation tool or a one-off script, save to `public/og-hero.png`, commit. If it gets stale, regenerate manually.
- **Hero example mobile rotation**: Random pick on page-load from the three pre-rendered images. No analytics on which performs best at v1; revisit if data signals one is dragging others down.
- **Photographer credits surface**: A modal triggered by the footer link. Content is generated at build time from `photos.json`'s `credit` field. No need for a separate credits page.
- **Theme color in dark-mode contexts**: `theme-color` defined only for light context (no `media="(prefers-color-scheme: dark)"` variant). The site has no dark mode; users on dark-mode-preferring devices will still see the light cream palette.
